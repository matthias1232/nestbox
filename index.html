BUILT FOR THE NEW LOCAL STACK

From the first agent experiment to a governed AI environment.

OpenShell sits at the core of the Nestbox design: a safe runtime developed by NVIDIA for controlled AI-agent execution. Nestbox surrounds it with a purpose-built control plane, policy, mounts, models, tools and observability.

ONE PLATFORM · CLEAR BOUNDARIES

Every responsibility in its own lane.

React Admin provides the local control experience. FastAPI exposes a versioned control API. A gateway governs routes. OpenShell mediates execution. Every agent, model or OCI workload runs in its own sandbox.

THE CAPABILITY LAYER

One system. Many controlled ways to build.

01 / 06
01

LOCAL MODELS

Choose a model. Deploy a governed runtime.

Select a validated Nemotron profile, deploy a dedicated model sandbox, then start, stop, inspect health and read logs from one place. Agent access is routed through approved policy paths — never direct host access.

  • Dedicated model cache and lifecycle
  • Validated local GPU profiles
  • Approved consumers and gateway routing
02

AGENT WORKSPACES

Start from a template. Keep every capability explicit.

Choose an agent runtime, preinstalled developer tools, approved MCP capabilities, a project scope and a reusable policy. Templates provide a secure starting point, not blanket host access.

  • Development, research and custom templates
  • Git, approved GitHub access and project CLIs
  • Governed MCP tools per sandbox
03

PROJECT MOUNTS

Attach a project where it belongs — then remove it.

Projects are capabilities, not background assumptions. Attach a volume read-only or read-write, detach it instantly, or reassign it to a different sandbox with an audit trail.

  • Read-only and read-write grants
  • No implicit shared filesystem
  • Unmounted means inaccessible
customer-portalproject volume
Read/write → Coding sandbox
Read-only → Research sandbox
No mount → No access
04

POLICY + EGRESS

See every route before it becomes a risk.

Create reusable policies for mounts, tools, DNS, TLS, proxy routing and destinations. The planned gateway can surface live egress decisions and forward redacted structured events to syslog.

  • Validate, version, diff and roll back
  • Allow/block decisions per sandbox
  • Optional observation path; TLS inspection off by default
05

PROTECTED OCI APPS

Bring an image. Put governance in front of it.

Connect Docker Hub, private OCI registries or your approved image source. Deploy application images to isolated sandboxes and place OpenShell and gateway policy in the path for AI-capable workloads or controlled egress.

  • Public and private registry references
  • Secret references, never image-embedded credentials
  • One lifecycle and policy surface
06

IMAGE BUILDER

Configure once. Boot into a ready environment.

Generate inspectable Ubuntu seed bundles for bare metal, Proxmox, a cloud VM, WSL or local GPU hardware. Network, DNS, NTP, trusted CA and proxy settings can be preseeded; secrets are always added after first boot.

  • Cloud-init and autoinstall preview
  • Static IP or DHCP, CA and proxy support
  • Future remote ISO jobs and artifact history
