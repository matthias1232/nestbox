# ADR 0024 — The sandbox SSH key is a one-time download, and the database holds a locator

Status: Accepted
Date: 2026-10-27

## Context

Operators want `ssh` into a sandbox, and remote-editor flows (VS Code Remote-SSH,
Claude Code, Antigravity) need a key rather than a password. That means a private
key has to exist somewhere and reach the operator once.

ADR 0005 already says secrets are locators, never values. An SSH private key is
the clearest case: it is long-lived, it grants a shell, and a database backup
containing it is a backup containing shell access to every sandbox.

## Decision

**A key pair per sandbox, generated by the control API.** `sandbox_ssh_keys` holds
the public half, a `file://` locator for the private half, the SHA256 fingerprint,
when it was created, and when it was downloaded. The file is 0600 in the node's
secret directory.

**The private key crosses the wire exactly once.** `GET /sandboxes/{id}/ssh-key/
download` returns it and stamps `downloaded_at`. A second call answers 410
`key.already_downloaded`. The response type (`SshKeyDownload`) is separate from
the record type, so no list or detail endpoint can serialise the material by
accident, and `private_key_ref` is `#[serde(skip_serializing)]`.

**Rotation is the recovery path.** `POST /sandboxes/{id}/ssh-key/rotate` deletes
the old file, writes a new pair, and resets the download flag. Deleting first
matters: a crash between the two steps must not leave two usable keys.

**The public key is mounted, not copied.** It lives under the sandbox's persistent
root as `authorized_keys`, read-only, so it survives a container restart and is
part of the state an operator can inspect.

## Alternatives rejected

**Store the private key encrypted in the database.** It makes the key part of
every backup and every replica, and moves the protection to one more secret.

**Let the operator generate the key and paste the public half.** Fewer moving
parts, but then the private key is created in a browser, and "download it once"
is the same UX with worse guarantees.

**Password authentication.** No.

## Consequences

- Losing the one download means rotating. That is the intended consequence, and the
  console says so before the click.
- The key is scoped to one sandbox; there is no node-wide operator key.
- `sshd` in the image is configured `PasswordAuthentication no`, `PermitRootLogin
  no`, `AllowUsers nestbox`.

## What would invalidate this

Short-lived certificates signed by an SSH CA (with the key never stored at all)
would supersede this design and remove the download step entirely. It is the
better answer once there is an SSH CA to sign with.
